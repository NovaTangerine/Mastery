# Log Data Schema & Architecture Guidelines

This document defines the "atomic unit" of the QuestLog platform: the **Log**. 

To make features like **Playthrough Collectible Cards** and **AI Review Suggestions** work seamlessly, the `Log` schema is divided into three distinct sections:

1. **Core Relational Data** (Who, What, When)
2. **Session Metadata** (The raw stats for the session, which aggregate into the Playthrough Card)
3. **AI Analysis** (The semantic data for Reviews and Topics)

## The JSON Schema (Draft)

```json
{
  "log_id": "log_9a8b7c6d",
  "user_id": "usr_12345",
  "game_id": "igdb_7890", // Links to the unified game database (e.g., IGDB)
  "created_at": "2026-03-30T16:36:22Z",
  "updated_at": "2026-03-30T16:36:22Z",

  // --------------------------------------------------------
  // 1. SESSION METADATA (Aggregates to power Playthrough Cards)
  // --------------------------------------------------------
  "session_metadata": {
    "platform": "PlayStation 5",
    "playtime_delta_minutes": 150, // Time played in THIS session
    "total_playtime_minutes": 840, // Running total for this user/game up to this log
    "difficulty_level": "Hard",
    "completion_status": "In Progress", // e.g., "Started", "In Progress", "Rolled Credits", "100%"
    "custom_milestone": "Defeated the Abyss Watchers" // Optional user input
  },

  // --------------------------------------------------------
  // 2. THE CONTENT (Powers the Social Feed & Micro-posts)
  // --------------------------------------------------------
  "content": {
    "blocks": [
      {
        "id": "blk_1",
        "type": "paragraph",
        "text": "Finally beat the Abyss Watchers. The second phase caught me completely off guard, but the music was incredible."
      },
      {
        "id": "blk_2",
        "type": "image",
        "url": "https://storage.questlog.com/.../abyss_dead.jpg",
        "alt_text": "Victory screen"
      }
    ]
  },

  // --------------------------------------------------------
  // 3. AI ANALYSIS (Powers Reviews & Topics)
  // --------------------------------------------------------
  "ai_analysis": {
    "processed_at": "2026-03-30T16:36:25Z",
    "sentiment_score": 0.85, // -1.0 (frustrated) to 1.0 (thrilled)
    "primary_emotion": "Triumphant",
    
    // Broad categories for the Review Builder
    "topics_detected": [
      "boss_fight",
      "soundtrack",
      "difficulty_spike"
    ],
    
    // Specific entities extracted from the text
    "entities_mentioned": [
      "Abyss Watchers"
    ],
    
    // A 1-sentence summary generated by AI for this specific session
    "session_blurb": "Overcame a major boss fight, praising the surprise second phase and incredible soundtrack.",
    
    // Highly specific prompts generated by AI to help them write their final review later
    "suggested_review_prompts": [
      "You mentioned the music during the Abyss Watchers fight—how did the soundtrack impact your overall experience?",
      "Discuss the difficulty curve leading up to the Abyss Watchers."
    ],
    
    "contains_potential_spoilers": true
  }
}
```

## How this Schema Powers the Platform

### 1. Playthrough Collectible Cards (Commemorating the Journey)
Because cards commemorate an *entire playthrough* rather than a single session, the system will query all logs for a specific `user_id` and `game_id` when the user clicks "Generate Card".
* **Stats:** It grabs the `total_playtime_minutes` from the final log, the `platform`, and the final `completion_status` (e.g., "Rolled Credits").
* **The Journey:** By looking at the `custom_milestone` or `session_blurb` fields across all logs, the AI can generate a holistic "Playthrough Summary" for the back of the card.
* **Visuals:** It pulls the official game cover art using the `game_id`.

### 2. AI Review Suggestions
When a user finishes a game and clicks "Write Review," the app queries all logs for that game to eliminate the "blank page" problem:
* **Topic Aggregation:** "I see you talked about `soundtrack` in 4 different logs, and `combat` in 12 logs. Do you want to add sections for Audio and Gameplay to your review?"
* **Prompting:** The UI displays a sidebar of the `suggested_review_prompts` aggregated from their logs to jog their memory.
* **Sentiment Graph:** Because we captured `sentiment_score` over time, the platform can generate a line graph showing their emotional journey through the game to include in their review (e.g., "You started out frustrated, but loved the second half!").

### 3. Event-Driven Architecture
By structuring the data this way, the AI does its job *asynchronously* in the background right after the user saves a log. By the time the user wants to generate a Playthrough Card or write a review weeks later, the semantic data is already perfectly formatted and waiting for them.
